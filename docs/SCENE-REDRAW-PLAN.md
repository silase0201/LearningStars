# `.scene` 元件重新繪製規劃

> 本文件中的 `.scene` 對應需求所寫的 `.sence`。本階段只規劃，不修改正式頁面與現有素材。

## 一、重新繪製目標

- 不再從完整設計圖裁切人物、星體與艙體，改為重新繪製乾淨的透明元件。
- 六題共用同一位孩子、太空衣、光影、線條粗細與色彩系統。
- 圖片內不包含標題、描述、ABCD、按鈕、框線或星空底色。
- 每個可移動或需要 RWD 調整的物件各自獨立，不合併成單張前景圖。
- 手機與桌機使用相同素材，透過 CSS 座標、比例與圖層重新排版。
- 保留目前的單選、下一題、進度跳題、滑入、點擊與選中效果。

## 二、目前素材需要改善的地方

- 部分星體裁切範圍包含相鄰星球、文字碎片或原圖背景。
- 人物、艙體、控制台與故事物件合併後，無法針對手機畫面個別縮放或移位。
- 部分物件在透明邊緣仍保留深色矩形或星空碎片。
- 第四題的四顆星球及第六題的四顆學習星屬於題意物件，不應與隨機裝飾星體使用相同配置邏輯。
- 六題的視覺焦點與文字安全區尚未使用同一套座標規格。

## 三、新的 `.scene` 圖層

```text
.scene                              isolation root
├─ .scene-backdrop                  z-index: 0，CSS 漸層與星空
├─ .celestial-field                 z-index: 10–19，隨機裝飾星體
├─ .scene-stage                     z-index: 20–59
│  ├─ .scene-component--environment z-index: 20–29
│  ├─ .scene-component--story       z-index: 30–39
│  ├─ .scene-component--character   z-index: 40–49
│  └─ .scene-component--foreground  z-index: 50–59
├─ .scene-copy                      z-index: 60
└─ .scene-controls                  z-index: 70
```

### 圖層責任

- `scene-backdrop`：只用 CSS 與現有動畫 PNG 星空，不需要題目專用背景圖。
- `celestial-field`：只放不影響題意的月球、小行星、遠方星球及銀河。
- `environment`：地表、艙窗、圖書館平台等環境元件。
- `story`：神秘盒、四顆題意星球、四本書、四顆學習星等關鍵物件。
- `character`：孩子、機器人及需要保持角色一致性的角色元件。
- `foreground`：控制台、艙框、地面前緣等用來建立景深的遮擋元件。
- `scene-copy`：關卡、標題與描述，全部維持 HTML 文字。

## 四、共同繪製規格

### 美術風格

- 兒童友善的精緻 3D 卡通插畫。
- 圓潤輪廓、清楚表情、柔和體積光，不使用寫實恐怖或過度複雜材質。
- 主色為深海軍藍、星空藍及青色光；重點色使用金黃、橙色、綠色與紫色。
- 同一孩子固定臉型、髮型、眼睛比例、太空衣造型與胸前星形徽章。
- 太空衣、控制台及載具的高光方向統一由左上方照射。

### 透明素材

- 主檔使用透明 PNG，輸出時保留完整 alpha channel。
- 正式頁面另輸出透明 WebP；HTML 使用 WebP，PNG 作為 fallback。
- 長邊至少為實際最大顯示尺寸的兩倍，避免高 DPI 螢幕模糊。
- 物件四周保留約 4% 安全透明邊界，不可切到發光、手指、書角或星環。
- 不加入矩形底色、星空、文字、外框或無法分離的投影背景。
- 接地陰影如果會隨排版改變，獨立輸出成 `shadow` 元件；不可烘焙在人物圖底部。

### 統一座標

- `.scene` 使用百分比座標，元件以自身視覺中心或底部中心作為 anchor。
- 桌機參考畫布為 `1200 × 720`，手機參考畫布為 `900 × 900`。
- 桌機文字安全區：水平 20%–80%，垂直 4%–39%。
- 手機文字安全區：水平 10%–90%，垂直 4%–43%。
- 主要人物及故事物件不可進入文字安全區。
- 元件不依賴 `object-fit: cover` 裁切；每個元件自行定位與縮放。

## 七、JavaScript 資料格式

每個元件保存桌機與手機位置，不把題目差異寫死在 CSS selector：

```js
components: [
  {
    image: "character-child",
    role: "character",
    anchor: "bottom-center",
    desktop: { x: 72, y: 100, width: 35, z: 46 },
    mobile: { x: 74, y: 100, width: 48, z: 46 }
  },
  {
    image: "story-mystery-box",
    role: "story",
    anchor: "bottom-center",
    desktop: { x: 48, y: 96, width: 34, z: 35 },
    mobile: { x: 42, y: 96, width: 42, z: 35 }
  }
]
```

- `x`、`y`、`width` 使用場景百分比。
- `z` 僅能使用該角色層允許的範圍。
- 角色或故事物件可以覆寫手機位置；沒有覆寫時沿用桌機設定。
- 圖片元素維持 `alt=""`，題意由相鄰 HTML 標題及描述提供；若未來圖片本身成為操作元件，再補具體替代文字。

## 八、重新繪製流程

1. 先建立一張共用角色樣式表，固定孩子、機器人、太空衣與光影。
2. 以樣式表作為六題後續重新繪製的參考，不直接從舊場景裁切。
3. 先完成 q01，輸出桌機 `1200 × 720` 與手機 `900 × 900` 組合預覽。
4. 確認角色一致性、文字安全區與圖層後，再繪製 q02–q06。
5. 對每個元件檢查透明邊緣、殘字、背景碎片及裁切缺口。
6. 批次輸出 PNG/WebP，並建立檔名、尺寸及容量報告。
7. 新增共用 `renderSceneComponents()`，依題目資料產生 `<picture>` 元件。
8. 將語意星體從 `celestial` 隨機陣列移至固定 `components`。
9. 逐題調整桌機與手機座標，不用圖片裁切補救版面。
10. 完成六題視覺驗收後才替換正式素材並封存第一版場景。

## 九、互動效果

- 隨機裝飾星體保留目前的緩慢漂移與景深效果。
- 故事元件使用 5–8 秒、位移不超過 `0.35rem` 的輕微呼吸或浮動。
- q01 控制台按鈕可依序柔和發光，但不模擬可點擊狀態，避免和答案按鈕混淆。
- q03 警示燈可慢速明暗變化；減少動態模式下保持常亮。
- q04、q05、q06 的四個故事元件可用不同延遲浮動，但基線與順序固定。
- 所有動畫在 `prefers-reduced-motion: reduce` 下停止。

## 十、驗收條件

- 六題人物看起來是同一位孩子，服裝與徽章一致。
- 所有元件邊緣完整，沒有文字、矩形底色、鄰近物件或原星空殘留。
- 桌機與手機不依賴 `object-fit: cover` 裁切主要人物或故事物件。
- q04、q05、q06 的四個題意物件位置與 ABCD 順序固定。
- 關卡文字在 320、390、750、1280、1920 寬度均不被遮擋或溢出。
- 隨機星體永遠位於角色、故事元件、文字及按鈕後方。
- 正式素材只保留頁面會載入的 PNG/WebP；主檔與預覽放在 `source-images`。
- CSS 的所有 `font-size` 繼續使用 `rem`。
- 鍵盤操作、單選、下一題、回上一題、進度跳題及完成流程不受影響。

## 十一、建議的核准節點

為避免六題全部完成後才發現風格不符，重新繪製分三次核准：

1. **角色樣式核准**：孩子、機器人、太空衣、色彩及光影。
2. **q01 組合核准**：確認元件拆分方式、桌機與手機構圖。
3. **六題整體核准**：確認故事連續性後，再替換正式素材。
